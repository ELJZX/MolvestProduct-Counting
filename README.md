# Система учёта продукции (молочный комбинат)

Веб-приложение на **Python / Django** для подсчёта продукции, прошедшей под
оптическими датчиками. Количество фиксируется контроллерами **ОВЕН** и
передаётся на сервер по HTTP API, где хранится в **PostgreSQL**.

## Возможности

- **Авторизация и роли**: Администратор / Оператор / Наблюдатель
  (профили пользователей, разные уровни доступа). Для администратора в шапке —
  кнопка «Админка» (администрирование Django) и текущее время.
- **Вкладки**:
  - *Главная* — статистика предприятия: цеха, линии, линии в работе,
    количество продукции за сегодня, производительность за час.
  - *Цеха* — список цехов с краткой статистикой: **продукция за сегодня** и
    **простои за сегодня (минуты)** по всем линиям цеха.
  - *Линии* — линии (с фильтром по цеху), текущий продукт, активное задание,
    количество за сегодня.
  - *Отчёты* (объединена с «Отчётами о простоях»): выбор нескольких линий и
    периодов; **график по каждой линии**; **минуты простоя — красные столбики
    с чёрными полосками высотой в максимальную производительность за период**
    (время простоя хорошо видно); ползунок **«Отображать простои производственной
    линии»**; подсказки при наведении (кол-во, линия, продукт, картинка, код 1С);
    масштабирование кнопками (окно 10, 30, 60 минут или весь период + прокрутка); выгрузка отчётов:
    по продукции (каждая линия отдельным разделом + итог по всем линиям в конце)
    и по простоям.
  - *Продукция* — справочник продукции: администратор добавляет коды, **цех**,
    код 1С, изменяет **цвет на диаграмме** (RGB-сетка + пипетка) и загружает
    **изображение** (необязательное, показывается в подсказке графика).
    Одинаковые названия и коды 1С допустимы в разных цехах; код продукта уникален.
- **Линия (диаграмма)** — **реальное время**:
  - показывает скользящее окно последних 2 часов, **по умолчанию окно 10 минут**;
  - **обновление каждую минуту без перезагрузки страницы** + мгновенно по SSE
    (GET /api/v1/events/) при приходе данных контроллера;
  - столбики окрашиваются в **цвет продукта**; при наведении — **всплывающая
    подсказка**: количество за минуту, изображение продукта, название, код 1С;
  - **масштабирование кнопками** («+», «−», «Весь период») + прокрутка окна;
  - статичные графики за произвольные периоды — во вкладке **«Отчёты»**.
  - **масштабирование кнопками**: «+» увеличить, «−» уменьшить, «Весь период»;
    шаги окна — 10, 30, 60 минут; подписи оси времени и подсказка
    при наведении обновляются вместе с масштабом (на всех графиках проекта);
  - итоговое количество за выбранный диапазон + разбивка по продуктам;
  - **отчёты**: выгрузка в **XLSX** и **CSV** за выбранный диапазон.
- **API для контроллеров ОВЕН**: `POST /api/v1/counter/` (ключ `X-API-Key`).
- **Эмулятор линии** (отдельный сервис `line_simulator/`): окно браузера с
  **проверкой подключения к серверу**, выбором линий и продукта, насчётом по
  клику мыши — для тестирования без контроллера ОВЕН.
- **База данных**: PostgreSQL (настраивается через `.env`; для отладки доступен
  режим SQLite).

## Технологии

Python 3.14 · Django 5.0.6 · Django REST Framework 3.15 · psycopg2 ·
PostgreSQL · openpyxl (отчёты XLSX) · Pillow (изображения продуктов) ·

## Установка и запуск

1. Создайте базу данных PostgreSQL (по умолчанию `molvest`):

   ```sql
   CREATE DATABASE molvest ENCODING 'UTF8';
   ```

2. Настройте подключение в файле `.env` (лежит рядом с `django_app/`):

   ```ini
   DEBUG=True
   DB_ENGINE=postgresql
   DB_NAME=molvest
   DB_USER=postgres
   DB_PASSWORD=admin
   DB_HOST=127.0.0.1
   DB_PORT=5432
   # Ключ авторизации контроллеров ОВЕН
   CONTROLLER_API_KEY=super-secret-controller-key
   APP_TIME_ZONE=Europe/Moscow
   ```

3. Установите зависимости и выполните миграции:

   ```bash
   cd django_app
   pip install -r requirements.txt
   python manage.py migrate
   ```

4. Наполните базу демо-данными (справочник продуктов 001..999, цеха, линии,
   пользователи):

   ```bash
   python manage.py seed_data
   ```

   Демо-пользователи: `admin/admin123` (администратор),
   `operator/operator123` (оператор), `viewer/viewer123` (наблюдатель).

5. Запустите сервер:

   ```bash
   python manage.py runserver 127.0.0.1:8000
   ```

Откройте http://127.0.0.1:8000 — появится страница входа.

## Приём данных от контроллера ОВЕН

Контроллер отправляет **POST** на `/api/v1/counter/` с заголовком
`X-API-Key: <CONTROLLER_API_KEY>` (значение из `.env`).

Пример тела запроса (JSON):

```json
{
  "controller_id": "CTRL-001",
  "product": "105",
  "count": 1234,
  "at": "2026-08-17T08:00:00+03:00"
}
```

- `controller_id` — идентификатор линии (`Line.controller_id`);
- `product` — код продукта `001..999` (при смене ключа продукта сервер
  автоматически закрывает старое задание и открывает новое);
- `count` — **суммарное** показание счётчика за смену продукта (сервер сам
  считает приращение); вместо него можно передать готовое приращение `delta`;
- `at` — время измерения (ISO 8601; необязательно, по умолчанию «сейчас»).

Ответ: `{"ok": true, "delta": 25, "total_count": 60, ...}`.

## Симулятор контроллера (для отладки)

```bash
# Прямой вызов сервисного слоя, 5 минут
python manage.py simulate_controller --minutes 5

# По HTTP через API (проверяет весь стек), бесконечно
python manage.py simulate_controller --http

# С автоматической сменой продукта каждые 10 минут
python manage.py simulate_controller --http --switch-after 10
```

## API (кратко)

| Метод | URL | Описание |
|-------|-----|----------|
| POST | `/api/v1/counter/` | приём показаний контроллера (X-API-Key) |
| GET | `/api/v1/lines/<id>/chart/?from=&to=` | минутный ряд для диаграммы (с цветами/кодом 1С продуктов) |
| GET | `/api/v1/events/` | real-time события (SSE/socket): `line_update {line_id}` при новых данных |
| GET | `/api/v1/sim/lines/`, `/api/v1/sim/products/` | данные для сервиса-эмулятора (X-API-Key) |
| POST | `/api/v1/reports/chart/` | сравнение линий: `{"lines":[{"id":1,"from":"...","to":"..."}]}` |
| POST | `/api/v1/downtime/chart/` | данные для графиков простоев: линии, события, минутные ряды |
| GET | `/api/v1/health/` | проверка доступности сервиса |

## Логотип в шапке

Вместо иконки-коробки рядом с надписью «Молвест.Учет.Продукции» можно
показать своё изображение. Загрузка — в админке Django: *«Настройка системы»*
(`/admin/dashboard/systemconfig/1/change/`), раздел **«Оформление»** → поле
**«Логотип (в шапке)»**. Рекомендуется PNG с прозрачностью, высота ~30–40 px
(ширина до ~140 px). Пока логотип не загружен, показывается стандартная иконка.

## Запасной режим отчётов из файлов DBF

Система умеет строить отчёты и графики не только из базы данных, но и из
архивных файлов **DBF** (dBase III, минутные показания контроллеров, например
`20442023.dbf`, `30742024.dbf`).

- **Настройка** — в админке Django: *«Настройка системы»* (`/admin/dashboard/systemconfig/1/change/`):
  - **Источник данных** — «База данных (PostgreSQL)» или «Файлы DBF»;
  - **Папка с файлами DBF** — путь к папке с `*.dbf` (пусто — корень проекта,
    при отсутствии файлов в корне автоматически ищется подпапка `DBF VIKO`).
  На странице настройки показан список найденных файлов с количеством записей
  и диапазоном дат.
- В режиме DBF вкладка **«Отчёты»** работает по файлам: в списке «Счётчик»
  показываются **коды счётчиков**, найденные в именах файлов (например,
  `20442023.dbf` → код `2044`). Для выбранного периода (Смена/Сутки/Месяц/
  Квартал/Год/Период) система автоматически находит файлы этого счётчика,
  покрывающие период (в т.ч. через границу года), и строит отчёт или график.
  Экспорт XLSX/CSV работает так же.
- Имена продуктов берутся из справочника по коду (KOD); отсутствующие — «Продукт XXX».
- Отчёт о простоях в режиме DBF считает простой как непрерывный ряд минут
  с нулевым счётом длительностью более 1 минуты.

## Структура проекта

```
django_app/
├── manage.py
├── requirements.txt
├── django_app/            # настройки проекта
│   └── settings.py        # .env, PostgreSQL, приложения
└── dashboard/             # основное приложение
    ├── models.py          # Product (код, название, код 1С, цвет, изображение),
    │                      # Shop, Line, ProductAssignment, ProductionRecord,
    │                      # ControllerReading, UserProfile
    ├── services.py        # бизнес-логика (приём показаний, смена продукта,
    │                      # минутные ряды, простои, отчёты)
    ├── api.py             # REST API (контроллеры, диаграмма, SSE-события, эмулятор)
    ├── views.py           # веб-страницы
    ├── reports.py         # генерация XLSX / CSV
    ├── templates/dashboard/
    ├── static/dashboard/  # CSS, line_chart.js (обновление раз в минуту)
    └── management/commands/
        ├── seed_data.py           # демо-данные
        └── simulate_controller.py # симулятор ОВЕН (командная строка)
```

Отдельный сервис-эмулятор линии (окно браузера с кликами):

```
line_simulator/
├── server.py        # http-сервер-прокси (stdlib, без зависимостей)
├── run.bat          # запуск двойным кликом
├── README.md
└── static/          # index.html, app.css, app.js (окно браузера)
```
