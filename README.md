# Молвест.Учет.Продукции — система учёта продукции

> **Версия 1.6.2**

Веб-приложение на **Python / Django** для подсчёта продукции, прошедшей под
оптическими датчиками на производственных линиях молочного комбината.
Количество фиксируется контроллерами **ОВЕН** и передаётся на сервер по HTTP
API; данные раскладываются по минутным интервалам, на их основе строятся
диаграммы в реальном времени, отчёты за смены/сутки/месяцы/кварталы/годы и
расчёт простоев.

---

## Возможности

- **Авторизация и роли**: Администратор / Оператор / Наблюдатель (профили
  пользователей, разные уровни доступа). У администратора в шапке — кнопка
  «Админка», метка версии сборки и текущее время.
- **Шапка сайта**: логотип (файл `logo.svg` в корне проекта; если удалён —
  иконка), горизонтальные
  вкладки (Отчёты, Цеха, Линии, Продукция, Статистика), которые при изменении
  масштаба/ширины окна аккуратно переносятся и группируются; дата и время,
  имя пользователя, кнопки «Админка» и «Выйти».
- **Статистика** — карточки: линии в работе, продукция за сегодня, задания за
  сегодня, **простои за сегодня** (длительность в человекочитаемом виде:
  65 минут → «1 час 5 минут»); таблица линий в работе с производительностью
  (факт за час vs норма), статусом и простоем за сегодня в том же формате.
- **Цеха** — список цехов с краткой статистикой: число линий, продукция за
  сегодня, **время простоя** за сегодня (в формате «1 час 5 минут»), переход
  к линиям цеха.
- **Линии** — линии с текущим продуктом и статусом; кнопка
  **«График в реальном времени»** ведёт на диаграмму линии.
- **Диаграмма линии (реальное время)**:
  - скользящее окно (по умолчанию 10 минут), обновление раз в минуту и
    мгновенно по SSE (`GET /api/v1/events/`);
  - псевдо-3D столбцы, окрашенные в цвет продукта за каждую минуту;
  - запас по оси Y — 20% сверху от максимума;
  - всплывающая подсказка при наведении: количество, код и название продукта,
    дата/время, изображение, код 1С (окно не выходит за границы экрана);
  - столбики простоев (красно-чёрные) с подсказкой периода и **длительности**
    простоя («1 час 15 минут», для текущего простоя — точное время на момент
    просмотра);
  - масштабирование кнопками «+»/«−»/«Весь период» (окна 10/30/60 минут) и
    прокрутка окна (полоса, колесо мыши, перетаскивание).
- **Отчёты** (вкладка «Отчёты»): вкладки **Смена / Сутки / Месяц / Квартал /
  Год / Период**, типы отчётов (итоговый, подробный, по сменам, график,
  простои, валовый), выбор счётчика (линии), экспорт **XLSX/CSV**.
  - **Сравнение отчётов**: кнопка **«Добавить отчет для сравнения»** добавляет
    ещё один блок отчёта (свой счётчик, вкладка, тип и период) — до **8 блоков**
    одновременно; при попытке добавить девятый выводится ошибка «Превышен лимит
    сформированных отчетов». Каждый блок формируется и обновляется независимо
    (Ajax).
  - **Выгрузка всех отчётов**: «Выгрузить отчёты → Excel (XLSX)» — один файл,
    **отдельный лист на каждый отчёт** (заголовок, «Сформирован», мета-строки и
    все таблицы отчёта); «CSV» — все отчёты блоками в одном файле. Отчёты-графики
    («Сутки → График продукции») тоже выгружаются — каждый на своём листе
    с 6 графиками по 4 часа на листе A4.
  - Отчёты «Смена» и «Сутки» имеют единую структуру: шапка отчёта по строкам
    («Счетчик:», «Линия:», «Смена:» (для Смены), «Период:»), таблица с колонками
    «Код продукта | Заводской код | Наименование продукта | Кол-во | Нач.
    подсчета | Период | Время простоя» и итоговой строкой «ИТОГО».
    В шапке таблицы две верхние колонки объединены под «Код:», вторая строка
    шапки — «Продукта | Заводской» (на странице и в Excel).
  - «Сутки → подробный» делится на две таблицы по сменам (Смена 1, Смена 2).
  - Если за период не было продукции (или только код отладки 888) — выводится
    «Ошибка: Нет отчета за указанный период.» (слово «Ошибка:» красным).
  - Время простоя везде отображается как «45 минут», «1 час 15 минут»,
    «3 часа 10 минут».
  - **График за сутки → выгрузка в Excel**: графический файл с **6 диаграммами
    (по 4 часа каждая)** на одном листе A4 (альбомная ориентация, вписывается
    в одну страницу); каждый столбец — **одна минута** суток, цвет столбца —
    цвет продукта за эту минуту, над столбцом мелким шрифтом — количество;
    последний час суток подписывается «00:00», а не «24:00»; внизу листа —
    легенда: код, цвет и название всех продуктов на графиках. Данные графика
    спрятаны на скрытый лист «Данные».
  - График открывается в масштабе «окно 30 минут», каждая минута — столбик цвета
    продукта, простои — красно-чёрные столбики; вместо легенды — чекбокс
    **«Отображать график простоя»** (при выключении ширина столбцов не меняется).
    В подсказке над столбиком — количество, название и код продукта и **только
    время** («22:31») без даты на минутных графиках.
  - Кнопки масштаба «−» / «Весь период» / «+» не удерживают фокус и курсор
    (tabindex=-1 + blur), текст кнопок не выделяется.
- **Продукция** — справочник (коды 001..999, цех, код 1С, цвет на диаграмме,
  изображение, описание) с поиском и пагинацией; редактирование в модальном окне.
- **Переключение источника данных** (кнопка на вкладке «Отчёты»):
  база PostgreSQL или файлы DBF (запасной режим чтения архивов контроллера).
- **API для контроллеров ОВЕН**: `POST /api/v1/counter/` (ключ `X-API-Key`).
- **Эмулятор линии** (отдельный сервис `line_simulator/`) — окно браузера для
  тестирования без контроллера: кликами «насчитывается» продукция через тот же API.
- **Логотип в шапке**: файл `logo.svg` в корне проекта (рядом с `django_app/`;
  поддерживается и `logo.png`).

## Установка и запуск

### 1. Требования

- Python 3.12+ (`python --version`)
- PostgreSQL (служба запущена) — либо режим SQLite для отладки
- Все зависимости перечислены в `django_app/requirements.txt`

### 2. База данных

```sql
CREATE DATABASE molvest ENCODING 'UTF8';
```

### 3. Настройки (файл `.env` в корне проекта)

```ini
DEBUG=True
SECRET_KEY=django-insecure-dev-key-change-me
ALLOWED_HOSTS=*

DB_ENGINE=postgresql          # или sqlite для отладки
DB_NAME=molvest
DB_USER=postgres
DB_PASSWORD=admin
DB_HOST=127.0.0.1
DB_PORT=5432

# Ключ авторизации контроллеров ОВЕН
CONTROLLER_API_KEY=super-secret-controller-key

# Временная зона предприятия
APP_TIME_ZONE=Europe/Moscow
```

### 4. Виртуальное окружение и зависимости

```bash
python -m venv venv
venv\Scripts\activate            # Windows (PowerShell: .\venv\Scripts\Activate.ps1)
pip install -r django_app\requirements.txt
```

### 5. Миграции и демо-данные

```bash
cd django_app
python manage.py migrate
python manage.py seed_data
```

`seed_data` создаёт справочник продуктов (001..999), цеха, линии, счётчики и
демо-пользователей.

### 6. Запуск

```bash
python manage.py runserver 127.0.0.1:8000
```

Откройте **http://127.0.0.1:8000**.

## Приём данных от контроллера ОВЕН

Контроллер отправляет **POST** на `/api/v1/counter/` с заголовком
`X-API-Key: <CONTROLLER_API_KEY>` (значение из `.env`).

```json
{
  "controller_id": "CTRL-001",
  "product": "105",
  "count": 1234,
  "at": "2026-08-17T08:00:00+03:00"
}
```

- `controller_id` — идентификатор линии (`Line.controller_id`);
- `product` — код продукта `001..999` (при смене ключа сервер закрывает старое
  задание и открывает новое);
- `count` — суммарное показание счётчика за смену продукта (сервер сам считает
  приращение); вместо него можно передать готовое приращение `delta`;
- `at` — время измерения (ISO 8601; необязательно, по умолчанию «сейчас»).

Ответ: `{"ok": true, "delta": 25, "total_count": 60, ...}`.

## API (кратко)

| Метод | URL | Описание |
|-------|-----|----------|
| POST | `/api/v1/counter/` | приём показаний контроллера (X-API-Key) |
| GET | `/api/v1/lines/<id>/chart/?from=&to=` | минутный ряд для диаграммы (цвета, коды 1С, простои) |
| GET | `/api/v1/events/` | real-time события (SSE): `line_update {line_id}` |
| GET | `/api/v1/sim/lines/`, `/api/v1/sim/products/` | данные для эмулятора (X-API-Key) |
| GET | `/api/v1/health/` | проверка доступности сервиса |
| POST | `/reports/build/` | формирование отчёта (JSON: counter, tab, type, параметры) |
| GET | `/reports/export/?fmt=xlsx|csv&...` | выгрузка одного отчёта |
| POST | `/reports/export-multi/` | выгрузка нескольких отчётов в один файл (JSON: fmt, reports[]) |
| GET | `/logo.svg` | логотип проекта |

## Запасной режим: отчёты и графики из файлов DBF

Система умеет строить отчёты и графики не только из базы данных, но и из
архивных файлов **DBF** (dBase III, минутные показания контроллеров, например
`20442023.dbf`, `30742024.dbf`).

- **Переключение** — кнопка **«Источник: …»** на вкладке «Отчёты» рядом с
  «Выгрузить отчёт» (доступна администратору): «База данных (PostgreSQL)» ↔
  «Файлы DBF».
- **Папка с файлами DBF** — определяется автоматически: корень проекта
  (рядом с `django_app/`), а при отсутствии `*.dbf` в корне — подпапка
  `DBF VIKO`.
- В режиме DBF вкладка «Отчёты» работает по файлам: в списке «Счётчик»
  показываются **коды счётчиков**, найденные в именах файлов (например,
  `20442023.dbf` → код `2044`). Для выбранного периода автоматически находятся
  файлы счётчика (в т.ч. через границу года), строится отчёт или график.
- Имена продуктов берутся из справочника по коду (KOD); отсутствующие —
  «Продукт XXX».
- Простой в режиме DBF — непрерывный ряд минут с нулевым счётом длительностью
  более 1 минуты (запасной вариант; в режиме БД — пропуски данных работающей
  линии).

## Эмулятор линии (тестирование без контроллера)

1. Убедитесь, что сервер Django запущен.
2. Из папки `line_simulator`:

   ```bash
   python server.py
   ```

   (или двойной клик по `run.bat`).

3. Откройте **http://127.0.0.1:8050**: проверка подключения к серверу, выбор
   линий и продукта, клик по карточке — «насчёт» продукции через тот же API,
   что использует контроллер ОВЕН.

По умолчанию сервис обращается к Django на `http://127.0.0.1:8000` (можно
задать через переменные окружения `DJANGO_BASE_URL` и `CONTROLLER_API_KEY`).

## Симулятор контроллера (командная строка)

```bash
# Прямой вызов сервисного слоя, 5 минут
python manage.py simulate_controller --minutes 5

# По HTTP через API (весь стек), бесконечно
python manage.py simulate_controller --http

# С автоматической сменой продукта каждые 10 минут
python manage.py simulate_controller --http --switch-after 10
```

## Развёртывание (кратко)

- `DEBUG=False`, задайте `SECRET_KEY` и `ALLOWED_HOSTS` в `.env`;
- соберите статику: `python manage.py collectstatic`;
- запуск: gunicorn (`gunicorn django_app.wsgi:application`) или uWSGI,
  веб-сервер (nginx) проксирует на приложение и раздаёт `staticfiles/`.
