# ЗАПУСК ПРОЕКТА — пошаговая инструкция (Windows / PowerShell)

## 0. Что должно быть установлено
- Python 3.12+ (проверка: `python --version`)
- PostgreSQL 18, служба запущена (проверка: `Get-Service -Name "postgresql-x64-*"`)
- Всё остальное уже в проекте (виртуальное окружение `venv`, зависимости)

## 1. База данных (только при первом запуске)
Откройте терминал и выполните (пароль админа БД из `.env` — по умолчанию admin):

    $env:PGPASSWORD='admin'
    & "C:\Program Files\PostgreSQL\18\bin\psql.exe" -h 127.0.0.1 -U postgres -d postgres -c "CREATE DATABASE molvest ENCODING 'UTF8'"

Если база уже есть — пропустите шаг. Настройки подключения лежат в файле `.env`
(в корне проекта, рядом с папкой `django_app`): DB_NAME=molvest, DB_USER=postgres,
DB_PASSWORD=admin.

## 2. Активировать виртуальное окружение
В корне проекта (где лежит папка `venv`):

    .\venv\Scripts\Activate.ps1

(после этого в командной строке появится префикс `(venv)`).

## 3. Перейти в папку проекта

    cd .\django_app

## 4. Миграции (создание таблиц; только при первом запуске)

    python manage.py migrate

## 5. Демо-данные (продукты 001–999, цеха, линии, пользователи; один раз)

    python manage.py seed_data

## 6. ЗАПУСК СЕРВЕРА

    python manage.py runserver 127.0.0.1:8000

Откройте в браузере:  http://127.0.0.1:8000

## 7. Вход в систему
- admin / admin123      — Администратор (полный доступ + «Админка»)
- operator / operator123 — Оператор (может менять продукт на линии)
- viewer / viewer123    — Наблюдатель (только просмотр)

## 8. (Рекомендуется) Эмулятор линии — окно браузера для тестирования
Отдельный сервис (папка `line_simulator`). Сервер Django должен быть запущен.

1) Откройте НОВОЕ окно терминала и выполните:

    cd .\line_simulator
    python server.py

   (или просто запустите `run.bat` двойным кликом).

2) Откройте в браузере:  http://127.0.0.1:8050

3) Наверху страницы — панель **проверки подключения** к серверу Django
   (кнопка «Проверить подключение»; если сервер не запущен, окно покажет
   причину). Выберите линии (галочки), продукт (поиск по названию, коду
   001–999 или коду 1С), задайте приращение за клик и кликайте по карточкам
   выбранных линий — продукция «насчитывается», диаграммы и отчёты в системе
   обновляются в реальном времени (SSE). Это тот же API, что использует
   контроллер ОВЕН.

## 9. (Альтернатива) Симулятор контроллера ОВЕН из командной строки
В ОТДЕЛЬНОМ окне терминала (сервер должен быть запущен):

    cd .\django_app
    python manage.py simulate_controller --http --minutes 5

Каждую минуту он «присылает» показания по всем линиям через реальный API
`/api/v1/counter/` — диаграммы и отчёты наполнятся данными.

## 10. Остановка сервера
В окне сервера нажмите Ctrl+C.

---
Полезное:
- Проверка целостности:  `python manage.py check`
- Админка Django:        http://127.0.0.1:8000/admin/ (кнопка «Админка» в шапке)
- API контроллера:       POST /api/v1/counter/  с заголовком X-API-Key: <CONTROLLER_API_KEY>
- Смена БД на SQLite (для отладки без PostgreSQL): в `.env` поставьте DB_ENGINE=sqlite
- Привязка счётчиков DBF к линиям: админка Django → «Привязки счётчиков DBF к линиям»
